# LocalMedia 2：本机只读图库

新版本入口是 `Start-LocalMedia.cmd`（或 `python run_localmedia.py`）。后端默认在 `0.0.0.0:18765` 同时提供 API 和图库，启动后自动打开本机网页；局域网设备使用运行电脑的 IPv4 地址访问。端口可用 `--port` 修改，若只允许本机访问可传 `--host 127.0.0.1`。

局域网模式没有账号登录：同一局域网中能访问该端口的设备也能查看原图、修改设置和启动任务，只应在可信网络使用。Windows 防火墙建议只允许 TCP 18765 的 `LocalSubnet` 入站访问，不要做公网端口映射。

旧版 `backend/`、原 React 页面、旧数据库和缓存仍保留；新版本不读取旧分析数据，也不迁移或清空它们。新版前端入口为 `frontend/localmedia.html`，不包含聊天 Agent、相册评分、多用户和目录独立模型配置。当前分支按用户后续要求保持不变。

## 安装与运行

```powershell
conda env create -f environment-localmedia.yml
conda activate localmedia-v2
python run_localmedia.py
```

需要 Node.js（首次构建）、FFmpeg/FFprobe（视频）在 PATH。首次启动会安装前端依赖并构建；以后直接提供静态文件。更新前端后用 `python run_localmedia.py --build`。开发也使用同一个启动入口，无须另开 Vite 服务。

`requirements-localmedia-lock.txt` 记录本机测试通过的 Python 依赖版本，可用 `python -m pip install -r requirements-localmedia-lock.txt` 复现。FFmpeg 是独立程序，不包含在 pip 锁定文件中。

默认数据目录是 `data/localmedia-v2/`，可通过 `--data` 或 `LOCALMEDIA_DATA` 指定全新位置。SQLite 是事实来源；预览、抽帧和内存中的分块向量矩阵是可重建缓存。切勿将数据目录放在媒体根目录内部。

## 使用

1. 添加本机目录。递归扫描、读取信息、生成预览，不启动 AI。运行时监听变化；启动及每 15 分钟补扫，也可手动刷新。
   在“目录设置”中可关闭“启用此目录”；关闭后该目录及所有子目录会从工作区、搜索和后续扫描中隐藏，但数据库记录、预览、备注与描述均保留。可在工作区的“禁用目录”栏目重新启用。
   在目录树中选中任意子目录后，“目录设置”针对当前选中的子目录。普通子目录首次保存时会登记为独立可配置的嵌套目录，不移动或复制原文件。
   视频缩略图默认取第 10 秒，以避开常见片头；不足 10 秒的视频取中间位置，解码失败时回退到开头。
2. 在设置中分别选择描述和向量服务。Ollama 可读取本机模型列表；兼容 API 地址通常需包含 `/v1`。所有模型名称来自用户配置或服务列表，没有自动下载或切换。
3. Codex 模式通过官方 `codex app-server` 协议复用 ChatGPT 登录。设置页可启动官方登录并读取模型/额度。默认优先查找 `codex.exe`；也可填写可执行文件完整路径。
4. 选择文件后启动分析；未选文件时范围为当前目录或全库。默认跳过已经完成的分析，重新分析会在整个媒体成功后覆盖旧描述。
5. 文字搜索匹配文件名与描述；自然语言搜索先生成查询向量，再返回媒体网格。未生成向量的媒体可通过文字搜索找到。

选择云端描述服务时，将发送标准预览、视频抽帧、原始文件名、文件所在目录、目录背景和媒体备注；云端向量服务接收描述或查询文字。正式批量启动前界面要求明确确认。密钥只在后端 SQLite 设置中保存，公共设置响应及任务配置快照剔除密钥，错误日志不包含模型服务响应正文。

备注与描述分别编辑。备注和目录背景变化不会自动重分析。手动编辑描述会立即删除旧向量并排队编码。文件移动保留描述、备注、向量和进度，不把当前路径放入向量文本。

## 同步和媒体身份

发现媒体后先用路径、大小和修改时间写入数据库，并立即交给独立预览线程；完整 SHA-256 在预览队列清空后由低优先级后台线程补算，不阻塞扫描完成或缩略图生成。已有记录的大小和修改时间均未改变时沿用原哈希，不再次读取完整文件；任一项改变时立即把旧哈希置空、失效旧分析状态并重新排队预览和哈希。正在写入或处理过程中发生变化的文件稍后重试。

媒体身份同时使用文件系统身份（设备及文件索引）和完整 SHA-256。盘内移动优先匹配明确的文件身份；跨盘移动等后台哈希完成后，以唯一内容候选匹配。多个副本各显示一项，避免一对多副本按遍历顺序误合并。由于未变化判断使用大小和修改时间，外部工具若改写内容后又刻意恢复完全相同的大小和纳秒修改时间，普通补扫不会识别这次变化。

只有完整成功扫描的根目录才判定失联。不可访问的目录保留既有状态及预览，显示目录错误。失联媒体不参与默认列表和搜索；用户可以在失联视图手动清理数据库记录，接口不删除原文件。根目录搬家后修改根目录位置，下一次扫描按身份和内容匹配。

预览处理使用独立后台线程，不与 AI 请求共用队列。JPG/PNG/TIFF/WebP、HEIC/HEIF 和 RAW 使用 Pillow、pillow-heif、LibRaw/rawpy；RAW 优先内嵌预览，无预览时默认解码。原文件 EXIF 补足内嵌预览缺失的摄影信息。支持扩展名并不保证所有编码变体都能解码；失败保留占位及原因。

## 分析任务和额度

任务创建时固定媒体 ID 集合、模型、提示词、背景和抽帧配置；尚未完成后台哈希的媒体保持排队，哈希补齐后才固定来源哈希并开始执行。视频抽帧可选择“高质量”（定时帧加画面变化检测）或“快速”（只按时间定时抽帧）；快速模式省去整段场景检测，但可能漏掉采样点之间的短暂事件。图库中的“开始抽帧”会按当前设置和源文件哈希检查持久化缓存：完整视频直接跳过，未完成视频复用已有帧和场景段继续，未抽帧视频才从头开始；它不请求 AI，也不修改已有描述、分析状态或向量。设置页分别配置图片和视频并发数；调度器先按图片并发处理完所有图片，再按视频并发处理视频，两类分析不会同时运行。若视频阶段中新图片进入队列，已开始的视频先完成，期间不再补充视频，随后切回图片阶段。同一视频的分片仍按顺序执行。“最多使用的 CPU 逻辑核心数”通过进程亲和性限制独立 AI worker 及其 FFmpeg、Codex 等子进程，`0` 表示不限制，不影响网页服务进程。

视频解码可选 CPU、Intel 核显 Quick Sync 或 NVIDIA 独显 NVDEC，并用于视频预览、固定间隔抽帧和场景检测。硬件不支持当前编码或配置时，该视频自动尝试其他已选设备并最终回退 CPU，同时写入事件；场景相似度滤镜仍在 CPU 上运行。视频流程不设总并发上限，CPU、Intel 核显和 NVIDIA 独显分别按各自的解码并发数限流，AI 投送使用另一套独立并发限制并动态生效。任务中心分别显示当前抽帧数与 AI 分析数，文件队列保持创建时的固定顺序；抽帧进度按已完成的视频时长工作量显示百分比，高质量模式会同时计入定时取帧和场景检测两趟。等待解码或 AI 槽位不计入请求超时，本地 FFmpeg 不套用 AI 请求的固定超时。视频默认每 5 秒抽取基础帧，并按设置的采样帧率补充场景变化帧；所有成功抽出的帧都会持久保留。每批 6 帧、重叠 1 帧，每批存储事件记录及连续性上下文。长记录按层汇总，不设固定视频总帧数。只有最终描述和向量全部成功才发布媒体级结果。

抽帧缓存按媒体 ID、原文件内容哈希和场景检测配置持久化，不依赖分析任务是否存在。删除任务再重建时，固定时间帧会按时间点直接复用；每个已经完整处理的60秒场景分段也会直接跳过。源文件内容改变后哈希不匹配，旧帧只保留作历史记录，不会进入新分析。升级前生成的历史帧没有分段完成标记：图片本身可立即复用，但场景分段需要补验一次，之后即可跨任务续跑。

普通暂停停止新请求，等待当前请求保存。立即停止取消 HTTP/Codex turn 并终止当前 FFmpeg 子进程，未完成阶段恢复时重做，已完成批次不重做。中断不能退还已经发生的模型消耗。重启后的未完成任务保持暂停，必须手动恢复。恢复时重新计算源文件哈希；源内容已变不能沿用检查点。

单视频默认预算 1800 秒，0 表示不限时。阶段运行中定期写入实际耗时，包含失败重试，不包含排队或暂停。请求超时取单请求限制和剩余视频预算的较小值；Codex RPC 等待也使用同一个单请求超时设置，不另设固定 30 秒上限。分析任务使用创建时的设置快照，登录、模型列表和额度读取等服务操作使用当前设置。超预算的视频暂停，其余文件继续；提高上限后手动恢复。

Codex 每次派发前读取额度并监听更新，但额度仅用于状态展示，不再根据五小时或每周额度阈值自动暂停。额度不足时仍会继续派发，由 Codex 服务返回成功或失败；程序不购买额度、不兑换重置，也不自动切换其他服务。

## 向量模型切换

描述模型改变不自动分析。向量模型改变后使用设置页“保存并重建向量”；重建未完成时查询继续使用原空间。新分析和描述编辑继续维护当前活动空间。SQLite 保存每条向量的模型空间、维度、描述版本；索引按空间及维度分组，使用 NumPy 分块矩阵余弦检索，筛选通过独立媒体列完成。描述版本不匹配或失联的向量不参与查询。

## 开发验证

```powershell
conda activate localmedia-v2
python -m pytest tests_localmedia -q -p no:cacheprovider --basetemp=work/test-new-run
cd frontend
npm run build:localmedia
```

Windows 某些已有 pytest 缓存目录可能不可写；使用新的 `--basetemp` 和 `-p no:cacheprovider`。若 `conda run` 受终端编码影响，可直接运行该 conda 环境的 `python.exe`。

性能验证：从项目根目录设置 `PYTHONPATH=.` 后运行 `scripts/localmedia_acceptance.py --benchmark`。该脚本只创建隔离的合成数据库；不模拟外部模型延时或真实语义质量。

官方协议依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。本机生成的 App Server JSON schema 也用于核对实际安装版本。
